# Buddy UI Audit

Date: 2026-03-14

Scope: `lib/pages/*.dart`, `lib/widgets/*.dart`, `lib/app_theme.dart`, `lib/app_color_scheme.dart`

Verification methods:
- Manual code audit of all page and widget Dart files
- Contrast spot checks against light and dark tokens
- `flutter analyze` (clean)

## Anti-Patterns Verdict

Verdict: Pass, with some drift.

This does not read as generic AI-generated Flutter UI. The typography choices, warm-dark token set, and card treatment are intentional. The weak spots are not “AI slop” so much as local regressions:
- repeated selection-card patterns in onboarding flatten hierarchy
- a few theme-bypassing literals reintroduce generic status colors
- some custom pressables skip the shared interaction primitives and fall back to raw `GestureDetector`

## Executive Summary

- Total issues found: 12
- Severity split: 0 critical, 5 high, 4 medium, 3 low
- Most critical problems:
  1. Light theme breaks on hard-coded dark gradients in `workout_sessions_page.dart`
  2. Multiple text and status colors fail contrast in light theme
  3. Several important actions ship below the 44x44 touch-target minimum
  4. Onboarding and growth helper copy is repeatedly dimmed below AA through alpha-reduced text tokens
  5. A key home badge uses a white icon on a near-white gold tint in light theme
- Overall quality score: 7.4 / 10
- Recommended next steps:
  1. Remove theme-bypassing gradients and literal status colors
  2. Normalize low-contrast helper copy to theme-safe text tokens
  3. Fix undersized actions with the existing shared pressable primitives
  4. Sweep remaining custom `GestureDetector` controls for semantics and tap feedback

## Detailed Findings By Severity

### Critical Issues

No verified critical issues. Core flows remain usable and `flutter analyze` is clean.

### High-Severity Issues

#### 1. Hard-coded dark gradients break light theme cards
- Location: `lib/pages/workout_sessions_page.dart:314`, `lib/pages/workout_sessions_page.dart:623`
- Severity: High
- Category: Theming / Accessibility
- Description: Two `AppCard` instances inject fixed near-black gradient stops (`#191214`, `#141417`, `#201813`, `#16171A`) instead of using light-aware tokens.
- Impact: In light theme the content switches to dark-on-light text tokens, but the surface remains dark at the top-left. Measured contrast for light `textPrimary` on `#191214` is ~1.06:1, which makes content unreadable.
- WCAG/Standard: WCAG 2.2 AA 1.4.3 Contrast (Minimum)
- Recommendation: Replace literal gradients with `context.colors.tintedCardGradient(...)` or a theme-aware tokenized variant.
- Suggested command: `/normalize`

#### 2. BMI and empty-state status colors fail on light surfaces
- Location: `lib/pages/growth_page.dart:899`, `lib/pages/growth_page.dart:1483`, `lib/pages/growth_page.dart:1484`, `lib/pages/growth_page.dart:1485`, `lib/pages/growth_page.dart:1486`
- Severity: High
- Category: Accessibility / Theming
- Description: Growth uses literal green/blue/yellow/red values for helper text and BMI categories. These work on dark cards, but not on light cards.
- Impact: Verified light-theme contrast failures:
  - `#4CAF50` on the light card/background is ~2.5-2.8:1
  - BMI colors range from ~1.72:1 to ~3.18:1 on white
  These values are below AA for normal text.
- WCAG/Standard: WCAG 2.2 AA 1.4.3 Contrast (Minimum)
- Recommendation: Replace literal status colors with light/dark-aware semantic tokens, or add dedicated BMI range tokens to `AppColorScheme`.
- Suggested command: `/normalize`

#### 3. Helper and disclaimer copy is repeatedly dimmed below AA
- Location: `lib/pages/onboarding_screen.dart:3412`, `lib/pages/onboarding_screen.dart:3528`, `lib/pages/onboarding_screen.dart:3840`, `lib/widgets/onboarding_social_proof.dart:172`, `lib/widgets/onboarding_social_proof.dart:232`, `lib/widgets/onboarding_social_proof.dart:239`, `lib/widgets/onboarding_aha_moment.dart:483`, `lib/widgets/onboarding_aha_moment.dart:490`, `lib/pages/growth_page.dart:557`, `lib/pages/growth_page.dart:653`
- Severity: High
- Category: Accessibility
- Description: Several instructional and disclaimer strings use `textMuted.withValues(alpha: 0.3-0.6)` or similar reductions.
- Impact: These alphas push text below AA in both themes. Example: dark `textMuted` at 0.6 over `cardDark` is ~3.23:1; light `textMuted` at 0.6 over white is ~2.51:1. The copy becomes noticeably hard to read on the screens that rely on it most.
- WCAG/Standard: WCAG 2.2 AA 1.4.3 Contrast (Minimum)
- Recommendation: Stop dimming text tokens for readable copy. Use `textMuted` directly, or create a dedicated tertiary text token that still clears AA.
- Suggested command: `/harden`

#### 4. Several important actions are below the 44x44 tap-target minimum
- Location: `lib/pages/diet_plan_page.dart:2354`, `lib/pages/diet_plan_page.dart:2364`, `lib/pages/diet_plan_page.dart:2505`, `lib/pages/profile_page.dart:444`, `lib/pages/growth_page.dart:844`
- Severity: High
- Category: Accessibility / Responsive
- Description:
  - Meal completion toggle is a `28x28` `GestureDetector`
  - “Log Actual” uses `tapTargetSize: shrinkWrap` with a `30` px minimum height
  - Reconnect Health uses `tapTargetSize: shrinkWrap`
  - Edit-goal pencil action is effectively a 24-28 px affordance
- Impact: These controls are harder to hit on phones and are less forgiving for one-handed use, motor impairments, and larger text/scaling scenarios.
- WCAG/Standard: WCAG 2.5.5 Target Size (Enhanced); platform touch-target guidance 44x44 px minimum
- Recommendation: Route these actions through `AppPressable` / `AppSurfaceIconButton`, or raise their minimum size to `AppTheme.minimumTouchTarget`.
- Suggested command: `/harden`

#### 5. Home streak badge icon fails contrast in light theme
- Location: `lib/pages/home_page.dart:1419`, `lib/pages/home_page.dart:1427`
- Severity: High
- Category: Accessibility / Theming
- Description: The flame icon is hard-coded `Colors.white` on a light gold translucent fill.
- Impact: In light theme, the effective badge fill is close to `#F1ECE2`; white on that background measures about `1.18:1`, far below the 3:1 requirement for meaningful icons.
- WCAG/Standard: WCAG 1.4.11 Non-text Contrast
- Recommendation: Use a dark foreground on light fills, or compute the icon color from the resolved badge background.
- Suggested command: `/normalize`

### Medium-Severity Issues

#### 6. Macro and accent colors bypass the theme system
- Location: `lib/pages/home_page.dart:969`, `lib/pages/home_page.dart:984`, `lib/pages/home_page.dart:999`
- Severity: Medium
- Category: Theming
- Description: Macro cards still rely on literal accent colors rather than semantic tokens.
- Impact: They cannot be tuned centrally for light/dark contrast, and they drift from the otherwise tokenized design system.
- WCAG/Standard: Design system consistency
- Recommendation: Move these accents into `AppColorScheme` as semantic macro tokens.
- Suggested command: `/normalize`

#### 7. Many custom pressables skip the shared interaction primitives
- Location: representative examples in `lib/pages/home_page.dart:715`, `lib/pages/onboarding_screen.dart:2770`, `lib/pages/onboarding_screen.dart:3169`, `lib/pages/onboarding_screen.dart:3538`, `lib/pages/profile_page.dart:1724`
- Severity: Medium
- Category: Accessibility / Interaction
- Description: A large share of selectable cards and toggles are raw `GestureDetector` + `Container` combinations rather than `AppPressable`, `InkWell`, or button widgets.
- Impact: Press feedback, focus behavior, semantics, and hit-area guarantees vary by screen. This is a systemic maintainability and accessibility risk rather than a single broken control.
- WCAG/Standard: WCAG 4.1.2 Name, Role, Value; platform interaction guidance
- Recommendation: Standardize custom choice cards and chips on `AppPressable`, and reserve `GestureDetector` for gesture-specific behavior.
- Suggested command: `/harden`

#### 8. Share preview cards are hard-wired to dark tokens
- Location: `lib/widgets/progress_share_cards.dart:79-397`
- Severity: Medium
- Category: Theming
- Description: Share cards use `AppColorScheme.dark` directly throughout.
- Impact: This is acceptable for export art if intentional, but the in-app preview ignores the user’s theme and adds a parallel styling path that can drift from the design system.
- WCAG/Standard: Theming consistency
- Recommendation: Either document these widgets as intentionally theme-invariant export surfaces, or pass an explicit “share theme” object instead of reaching into `AppColorScheme.dark`.
- Suggested command: `/normalize`

#### 9. Some tertiary labels are dimmed too aggressively
- Location: `lib/pages/login_page.dart:182`, `lib/pages/profile_page.dart:727`, `lib/pages/workout_page.dart:2141`
- Severity: Medium
- Category: Accessibility
- Description: A few captions and eyebrow labels use `textSecondary/textMuted` with `0.72-0.75` alpha.
- Impact: These are less severe than the onboarding/body copy failures, but they still land under or near AA on light cards for small text.
- WCAG/Standard: WCAG 2.2 AA 1.4.3 Contrast (Minimum)
- Recommendation: Normalize them to full-strength muted text or slightly smaller, still-AA-safe token variants.
- Suggested command: `/polish`

## Patterns & Systemic Issues

- Alpha-reduced text is the main contrast problem. The token values themselves are mostly sound; the repeated `withValues(alpha: ...)` usage is what breaks AA.
- Theme bypasses are concentrated and easy to find: literal `Color(...)` values in `growth_page.dart`, `home_page.dart`, and `workout_sessions_page.dart`; direct `AppColorScheme.dark` usage in `progress_share_cards.dart`.
- Custom interaction surfaces are inconsistent. The codebase already has `AppPressable`, but many new UI widgets still use raw `GestureDetector`.
- Light theme is more fragile than dark theme. Most verified contrast failures only appear once a dark-surface assumption leaks into a light-surface screen.

## Positive Findings

- The theme foundation is strong. `AppColorScheme` and `context.colors` provide a solid token architecture.
- Shared primitives already exist. `AppPressable`, `AppPrimaryButton`, `AppSurfaceIconButton`, `AppCard`, and `AppSnackbar` are good building blocks.
- Many pages already handle overflow responsibly with `Expanded`, `Wrap`, `SingleChildScrollView`, ellipsis, and safe-area padding.
- Semantics are present in several critical flows, especially around forms, share actions, and status messaging.
- Static code health is good: `flutter analyze` returned no issues.

## Recommendations By Priority

1. Immediate
- Remove dark-only gradients from `workout_sessions_page.dart`
- Replace failing growth status/BMI colors with semantic tokens
- Fix the home streak badge icon contrast
- Raise all undersized high-value actions to 44x44 minimums

2. Short-term
- Sweep onboarding and growth helper/disclaimer copy for alpha-reduced text
- Replace key `GestureDetector` choice cards with `AppPressable`
- Tokenize remaining macro/status accent colors

3. Medium-term
- Normalize export/share preview theming strategy
- Standardize small utility affordances and tertiary label styling

4. Long-term
- Create dedicated semantic tokens for tertiary text, BMI ranges, and macro accents
- Build a reusable selectable-card component so onboarding/profile/growth stop reimplementing card selection behavior

## Suggested Commands For Fixes

- Use `/normalize` to align theme usage and replace hard-coded gradients and accent literals
